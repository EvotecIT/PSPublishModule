# PSScriptTools WPF dialogs: bounded hosted qualification

The default `New-WPFMessageBox` OK path and plain `Invoke-InputBox` path have original/generated visual and callback proof on the two installed Windows PowerShell hosts. Both functions remain hosted in Hybrid; this is no CLR translation or general WPF support claim. The [visual record](../../../m29a-wpf-dialogs-visual.json) follows the earlier [failure-path record](../../../m29a-wpf-dialogs-partial.json).

`Prepare.ps1` pins the external New-WPFMessageBox file and Utilities file by SHA-256, extracts the unchanged Invoke-InputBox AST extent, and preserves the original functions/icons layout through a conventional root module and contained dot-source paths. Supply the pinned PSScriptTools root and a new task-owned input directory. The information icon remains an external validation input. CompleteModule resource mode includes it inside the artifact.

Run `ObserveFailures.ps1` in fresh noninteractive `-STA` child processes for each original/generated module on both Windows hosts. Seven cases assert platform refusal, module-local injected assembly refusal, actual WPF invalid-brush conversion and input-title validation. The platform and assembly shadows are explicit boundary probes. These cases never call ShowDialog and prove no modal callback behavior.

`Observe.ps1` runs the actual message or plain input dialog in STA and requires one result of the correct type/value. `OperateVisual.ps1` starts only the selected PowerShell host with that driver, discovers the window by its owned process ID and exact title, captures its rendered content through `PrintWindow`, sets the synthetic input value when needed, invokes OK through UI Automation, and closes the owned child on failure. Use a new task-owned output directory per case and the same title for an original/generated image pair. Inspect both PNGs, compare their hashes and result JSON, and confirm empty stderr and child exit. The current proof covers both cases on PowerShell 7.6.6/`net10.0` and Windows PowerShell 5.1.26100.9444/`net472`.

The PowerShell 5.1 copy of the UTF-8 fixture driver has no BOM, so its sample Omega appears as mojibake in both original and generated message windows. That pair establishes parity on the observed host, not correct Unicode rendering. Cancellation, secure input, alternate/custom buttons, backgrounds/icons, the other four WPF functions, other platforms and full-module GUI behavior need separate proof. Advertised regions and owned helper methods are not complete workload execution credit.
