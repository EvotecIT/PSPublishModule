# Hybrid executable entry contract

Status: the bounded prebound string-entry route and a separate native script-entry artifact route are qualified on their stated targets. The broader variable/state/lifecycle contract below remains open.

Hybrid executables emit eligible named functions as CLR methods. The packaged program still calls `PowerShell.AddScript` for the authored entry script. For the bounded private-root route, script parameters bind once in that host and the existing scalar entry emission consumes their values through explicit region delegates. Ordinary native-function binding applies to named functions rather than rebinding this private root. The [repair evidence](../Benchmarks/PowerShellCompilation/Corpus/m29a-hybrid-entry-abi-repair.json) qualifies defaults/explicit parameters, sequential output, errors, authored mapping, exact compiler-bridge dispatch and emitted-source publication. Command regions still execute in PowerShell. A compiled named function called from a hosted root remains a separate coverage claim from a compiled script root.

The admitted body consists only of direct `Get-Date` or `ConvertTo-Json` commands, with no functions, includes, redirections, dynamic invocation, or script-block argument, and only simple string parameters. Arguments are literals or references to those bound parameters in the first command; later commands use literals only. An earlier hosted command can change a script parameter through `-OutVariable` or similar effects, so a later command may not consume the entry frame's stale parameter copy until state transfer is implemented. This small command set keeps script-state inspection such as `Get-Variable MyInvocation` on the hosted root until an invocation-context contract exists. Explain and build select the same ordered statement sequence; the packaged statements must still match the authored statements exactly. The bridge receives already-bound string values through an internal command in the original runspace. The generated root method is private and its hosted regions carry the authored document and offsets. This does not make either command runtime-free or qualify the wider forms listed below.

## Ownership and invocation

The packaged launcher parses process arguments; its PowerShell invocation owns the authored `param` block, defaults, validation, `$args`, common parameters, `#requires`, source/dependency declarations, and runspace lifetime. Those actions must occur once, in source order. The compiler owns only a selected executable body span and its typed operations. It must not turn the authored root into an ordinary public function and bind the same parameters again: an unbound default or a validation script can have effects, and `$PSBoundParameters` does not contain every defaulted value. A two-function probe on PowerShell 7 and 5.1 evaluated an omitted default twice and an explicitly bound `ValidateScript` twice when the outer function called the inner one with `@PSBoundParameters`.

The proposed entry is a private generated method with an explicit host entry frame. The frame carries the already-bound parameter values, bound-name set, remaining arguments, authored script path/root, invocation context needed by the selected operations, and a live output/error/stream and cancellation owner. The packaged script retains its prologue and invokes a hidden bridge at the selected body span. The bridge must use the existing runspace for runtime-resolved commands; it must not silently replace an unqualified command with a CLR intrinsic or invoke an authored parameter binder a second time. The entry method and its source map are separate from named-function methods and counts.

The bounded `param([string] $Pattern = 'yyyy'); Get-Date -Format $Pattern` root now emits through this private route. Its command remains a hosted region. Earlier basic-function admission comparisons motivated keeping root eligibility independent of public cmdlet metadata; they do not describe the current named-function support, which has its own native host ABI. The entry compiler must preserve the script's binding semantics rather than manufacture advanced-function metadata.

Source closure and shaping must be one decision shared by `explain` and `build`. The compiler may replace a root span only when its parsed source checksum, statement order, contained dependency closure, generated entry frame, and host-effect contract all agree. It should reuse the canonical bound pipeline and source remapping rather than a new syntax whitelist or a special case for `Get-Date`. An unsupported root remains the authored hosted script, with an exact blocker in the explanation. Strict continues to use its runtime-free entry and rejects host-dependent forms.

## Observable contract

The first admitted route must prove these behaviors, or reject a root that observes one not yet implemented:

- Parameter conversion, optional defaults, validation effects, aliases, positional and named arguments, `$PSBoundParameters`, and `$args` occur once with the same values and errors.
- Local functions and contained dot-source declarations are available at the same source point. Runtime command lookup and shadowing happen at invocation, in the same runspace.
- Success output preserves zero/one/many records, ordering, CLR value types, collection enumeration, and the no-output versus `$null` distinction. Warning, verbose, debug, information, and error records retain their routing and preferences.
- `return`, `exit`, caught and uncaught errors, `$?`, stopping, `finally`/`clean`, and repeated invocation preserve their authored effects. The bounded native-root empty/scalar early-return-through-`finally` case below has artifact proof; other transfers require their own proof and remain hosted when the owner cannot preserve them.
- `$MyInvocation`, `$PSCommandPath`, `$PSScriptRoot`, caller scope, and module/session state must refer to the authored script context when read. A generated method must not expose its private bridge identity as the authored command.

## Qualification sequence

1. Build a source-mapped synthetic entry through the shared semantic pipeline with Hybrid host capabilities. Keep its method and disposition distinct from named functions. Compare `explain` and build selection on the same source before executing it.
2. Add the private host entry frame and bridge. Keep the authored parameter/prologue execution, and replace the root body only after all required frame fields and transfer effects are available. Refuse overlapping edits, source changes, and declaration order that the bridge cannot preserve.
3. Compare an ordinary generated launch with the original on the claimed host. Start with the dynamic-format date script as a focused binding/command-resolution probe, then the already pinned, unchanged offline Fibonacci application as the standalone portfolio workflow. The latter currently has one emitted named helper but a hosted root; count a new root operation only after the generated body is demonstrably invoked. Do not redistribute its externally pinned source without license evidence.
4. Exercise omitted and explicit parameters, a side-effecting default/validation control, zero/one/many output, a shadowed command, relevant streams, a caught error, `return`, `exit`, stopping/cleanup, and repeated launch. Record any rejected case as a specific hosted boundary, not a passing compiled case. Run focused compiler checks and the affected artifact/host proofs; reserve the broad matrix for an integration candidate or a contract it alone covers.

The first claimed target may be `net10.0` on Windows x64, where the existing standalone generated workflow was observed. PowerShell 5.1 can serve as an original-source oracle, but this does not claim a generated `net472` executable or other platforms without their own artifact execution.

## Native script invocation owner: qualified foundation

The fixture-only [native script entry evidence](../Benchmarks/PowerShellCompilation/Corpus/m29a-native-script-entry-owner.json) identifies an existing shared owner for richer roots: parse a fresh authored script AST, install compiled clause callbacks in its independent native compilation data, and invoke it as a script. PowerShell owns the original parameter block once; the callback consumes the active invocation's variable cells and output pipe. This is an alternative to extending the scalar bridge with another command-name whitelist.

The direct `PowerShell.AddCommand(CommandInfo)` route is unsuitable for basic script binding: the PowerShell engine directly constructs the cmdlet processor for script CommandInfo. Both tested hosts rejected an extra positional argument that the original script accepted. Native call-operator dispatch preserves ordinary script binding; a compiler-owned try/rethrow preserves terminating validation failure state. See the [engine processor selection](https://github.com/PowerShell/PowerShell/blob/v7.6.5/src/System.Management.Automation/engine/hostifaces/LocalPipeline.cs#L847-L864) and [ordinary script dispatch](https://github.com/PowerShell/PowerShell/blob/v7.6.5/src/System.Management.Automation/engine/CommandDiscovery.cs#L531-L539).

The initial fixture-only checks passed 2/2. The generated-root fixture now replaces that handwritten prototype and preserves the same four cases: default/validation evaluation counts, constrained parameter rebinding, remaining arguments, bound-name membership, authored path/root, local writes, output values/types/order and one compiled callback. Validation rejection preserves error identity/category/message and Failed invocation state with no callback or body output.

The internal native root now uses the canonical binder, analysis, lowering and C# backend. It adapts a copy of the authored AST, preserving document identity and native source positions instead of inserting a textual function header. Its generated C# body passes the same four successful cases and binding rejection on both hosts. The [lowering record](../Benchmarks/PowerShellCompilation/Corpus/m29a-native-script-root-lowering.json) includes 8/8 focused checks, 5/5 existing Hybrid entry checks, one Strict executable sibling, a clean net472 build and an independent read-only review without actionable findings. This is internal lowering qualification; explain/build and the packaged launcher do not select this route yet.

The shared runtime now prepares the entry through native command discovery, checks a SHA256 of the decoded authored text, and installs callbacks in fresh compilation data. Ordinary script invocation retains authorization and parameter binding. The shared lazy clause installer leaves parameter attributes uninitialized until the native binder needs them. Both hosts perform authorization once; rejection performs no parameter attribute construction, default evaluation or compiled callback. Source mismatch and restricted invocation fail before those effects. Final focused checks passed 11/11, including existing basic-function siblings; one independent read-only review found no actionable issues. The [policy record](../Benchmarks/PowerShellCompilation/Corpus/m29a-native-script-entry-policy.json) records exact hashes and earlier failures. WDAC, signed execution policy and broader system/file policy remain unqualified.

The native artifact route is selected for an explicit `net10.0`/`win-x64` Hybrid target. It requires a single authored end-only source with a semantically eligible root, no types, requirements, dot-source closure, named lifecycle clauses, parameter-metadata commands, parent runtime/module state or provider effects. Ordinary top-level function declarations now use the existing native nested-function owner: each declaration registers at its authored statement, and its body must lower completely. Distinct PowerShell function names do not collide merely because a separate executable-method route would normalize them to the same CLR name. The route excludes caller-frame observations (`$MyInvocation`, `$PSCmdlet`, `$input`), function/alias drive mutation, nested `exit`, late declarations and other unqualified child bodies. The root may use typed operations and direct `Write-Output`, `Write-Host`, `Write-Warning`, `Write-Verbose`, `Write-Debug`, `Write-Information` or `Write-Error` sites without redirection or dynamic invocation. These sites remain PowerShell command regions in the active invocation, preserving runtime lookup and stream routing; a same-source function named `Write-Warning` keeps its authored command lookup. Other commands retain the scalar route when it qualifies or the unchanged authored script fallback. Strict remains fail closed. The native artifact uses the exact authored text as its packaged script, validates the generated payload through the existing extraction hash and reviewed dependency lock, and invokes the source-locked compiled factory through ordinary script dispatch. Explain and build use the same planner and resolved explicit target contract.

The unchanged MIT-licensed external Baklava script is the first offline application proof: its loop/string operations run through an emitted CLR method while its `Write-Output` remains PowerShell-owned. Original and generated Windows x64/net10 launches produce the same 21 lines, exit code and error stream. A synthetic artifact separately compares omitted/explicit binding, validation, remaining arguments, local loop output and terminating error behavior. The generated source publication includes the exact packaged script and factory/launcher wiring. These results qualify that bounded route, not arbitrary command-bearing roots or a runtime-free program. The [artifact record](../Benchmarks/PowerShellCompilation/Corpus/m29a-native-script-artifact.json) contains hashes, test results and limitations.

The unchanged MIT-licensed external Quine script qualifies one additional command form: a `Write-Host` site after a compiled string assignment. Its format expression remains in the hosted command argument. Original and generated Windows x64/net10 launches match stdout, stderr and exit code; the generated artifact publishes the compiled root factory, preserves the authored source and records a runtime-routed command. A synthetic compiled `for` loop alternates `Write-Host` and `Write-Output` and matches all six records in order. Redirection and another stream command still retain the hosted root in focused explain checks. This is a hosted command inside a compiled root, not CLR translation of `Write-Host` or full information-stream and command-shadowing qualification. The [Write-Host record](../Benchmarks/PowerShellCompilation/Corpus/m29a-native-script-writehost.json) gives the exact scope.

The declaration-bearing route has synthetic original/generated Windows x64/net10 proof for three top-level helpers, including `Invoke` and two names that share a normalized CLR identifier. The [declaration record](../Benchmarks/PowerShellCompilation/Corpus/m29a-native-script-declarations.json) states the implementation limits. The unchanged external Fibonacci script then qualified an emitted root and helper on that same generated host with a reviewed lock and exact original/generated output; its [application record](../Benchmarks/PowerShellCompilation/Corpus/m29a-native-script-declarations-external.json) also records the substantial recursive-call cost and absent redistribution license. Next, expand the source/dependency and caller-context contract before admitting includes, other commands, full streams, dynamic invocation, broader `return` forms, `exit`, stopping/cleanup or caller metadata. Replacing an entire packaged end body must never discard generated-function registration. Broader system policy (including WDAC and signed file modes) and other target hosts need separate execution proof. No module-function count changes from script-root admission.

A focused native-root artifact now interleaves `Write-Warning` and `Write-Output` inside a compiled `for` loop. Original and generated Windows x64/net10 processes match exit code, warning/success stdout order and empty stderr. A second artifact declares an authored `Write-Warning` function and proves that the same-source shadow runs instead of the built-in warning cmdlet. This qualifies direct warning stream output and that authored lookup shape only. Warning common parameters, preferences, imported shadows, broader stream shapes and hosts remain open; the named-module inventory is unchanged.

The adjacent direct verbose, debug and information commands also match original/generated process output when their explicit common action parameters request visible records. A separate error artifact compares continuing `Write-Error` with `-ErrorAction Stop`: the former reaches later success output and exits zero, while the latter stops before later output and exits one. Both generated roots are emitted and runtime-routed on Windows x64/net10. Exact error text formatting/record identity, other preference settings, imported shadows and non-Windows hosts are not qualified by these probes. The compiled root continues to host every admitted command.

The existing native-root lowering also preserves an early `return` from a compiled `for` loop inside `try`/`finally`. A focused reviewed-lock Windows x64/net10 artifact matches ordinary `pwsh -File` for omitted and explicit stop indices, empty and scalar return values, success-output order, and the `finally` record; fallthrough continues after the `try`. The compiled ledger marks the root emitted and runtime-routed. The nested-`exit` packaging guard remains in force. This synthetic contract check does not establish an unchanged external application using top-level `return`, other return-value cardinalities, `exit`, `clean`, caller-frame behavior, or another generated host. See the [assessment](PowerForge.PowerShellCompilation.Assessment.md#native-script-root-bounded-return-through-finally).

The native-root route can also surround a terminal ordinary `ForEach-Object { ... }` process pipeline with compiled statements. The complete pipeline stays in the active PowerShell invocation.
