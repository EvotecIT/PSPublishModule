The first bounded `switch` slice now recovers only a direct, top-level exact switch over the same authored `[string]` parameter in a Hybrid native function. It rejects preceding commands, member calls, script blocks, and direct rebinding that could remove the parameter's type constraint. A synthetic original/generated probe also removes and recreates the parameter as an array: that function remains hosted. On the unchanged PSSharedGoods packet, `Convert-Size` and the deprecated `Set-EmailBodyReplacement` gain complete methods on both targets, with no previously emitted method or promoted region lost. The PowerInfoblox command-result condition still needs success-stream cardinality and local-call qualification; it cannot inherit this parameter-only rule.

A second bounded Hybrid slice collects success records from direct `[Array] $target = foreach (...) { ... }` assignments through the existing native output collector. Unchanged PSSharedGoods `ConvertFrom-ScriptBlock` gained a complete method on both targets and matched four offline original/generated cases on PowerShell 7 and 5.1. A later bounded slice admits direct literal member assignment from conditional statement output, such as `$Data.Properties = if (...) { ... }`. The unchanged PSSharedGoods `Get-ObjectPropertiesAdvanced` gained a complete method and matched offline original/generated cases on both hosts, with its hosted command regions still explicit. Its method replaces a former partial region. The current affected-packet count is **209/282** (`net10.0`) and **208/282** (`net472`); same-input CleanupMonster remains **43/68** on each, with no lost retained-function regions. These figures update only those packets, not the frozen five-module baseline table above. Other typed captures, return transfers, and command-result success streams still need their own contracts. The [assessment](PowerForge.PowerShellCompilation.Assessment.md#milestone-29a-sixth-slice--direct-member-conditional-output-capture) records exact evidence and limits.

Three small standalone sources make the distinction concrete on current `net10.0`: `Get-Date -Format yyyy` has **one typed Strict executable unit** and prior original/generated Windows x64 execution proof; `param([string] $Pattern); Get-Date -Format $Pattern` and `param([int[]] $Values); $Values | ForEach-Object { $_ * 2 }` each have **zero typed Hybrid executable units with hosted root source**, while Strict rejects each. The latter two were explain-only, not built or executed. Their Strict diagnostics respectively identify the nonliteral format boundary and the unqualified pipeline's missing runtime-free assignment contract. A direct dynamic-format `Get-Date` inside a named Hybrid function can already emit a CLR method with a hosted command region. The standalone difference is the **Hybrid executable script-root shaping rule**: it compiles eligible named functions but runs top-level statements through the packaged PowerShell entry point. Final explanations now identify this artifact boundary as `artifact.executable-script-root` when the script root was semantically eligible. A hosted Hybrid script can still run through PowerShell; that is not compiled execution credit. Earlier explanation hashes in the [assessment](PowerForge.PowerShellCompilation.Assessment.md#milestone-29a-current-portfolio-explanations) predate this added causal diagnostic.

**Ordinary command shapes also need attention.** The [module quickstart](PowerForge.PowerShellCompilation.ModuleConsumers.md) uses `Get-Date -Format yyyy`. A fresh one-function Hybrid build on both Windows hosts emits its complete CLR method with one hosted command region; the original and generated imports return the current integer year, and both honor a session function shadowing `Get-Date`. The earlier description of the whole function as retained was too broad. The new bounded intrinsic binds a literal `-Format` to a runtime-free string result only when command identity is safe: a canonical module-qualified call, or an unqualified call in a host-free Strict target without a local shadow. Dynamic formats, PowerShell's named `FileDate*` formats, other parameters, and an unqualified Hybrid call keep runtime resolution. The no-argument `Get-Date` rule remains. PSScriptTools also reports unqualified `Write-Debug`, `Write-Host`, `Write-Warning`, `New-Object`, and `ForEach-Object`; PSSharedGoods reports `Write-Host` and `Select-Object`; `Out-String` is hosted in PSScriptTools. These are observed invocation forms, not claims that every use of each named cmdlet is unsupported.

The separate inspect-only external assessment reports **Locksmith 13/44** and **Locksmith2 21/100** complete emitted functions on `net10.0`, with no complete workload execution. Locksmith's unresolved authored AD parameter types must not be admitted by pretending they are CLR types in the generated artifact. Locksmith2 prominently hits unresolved `[OutputType]`, member calls in `catch`, and unavailable `ErrorRecord` reference shapes. `Test-IsADAdmin` and `Test-IssueExists` have documented hosted dispositions in the [assessment](PowerForge.PowerShellCompilation.Assessment.md); they are not safe targets for an AD execution probe. Provider calls such as `Get-AD*`, network requests, prompts, and installer operations remain explicit host/effect boundaries until separately qualified. For the next implementation selection, split each retained function's co-blockers and identify a safe unchanged-source workflow. The formatted-date quickstart, bounded `[OutputType]` forms, direct string-parameter `switch`, direct `[Array] = foreach` capture, and direct member conditional capture have qualified slices above; their unqualified variants remain explicit. The largest frozen diagnostic group was parameter metadata, but its 66 affected units were **not** 66 ready-to-compile functions. A support claim should name the exact form, mode, host, command-resolution assumption, and remaining PowerShell boundary, then show original/generated behavior and same-input no-loss results. The [M29a checklist](PowerForge.PowerShellCompilation.NextMilestones.md#milestone-29a--make-ordinary-powershell-forms-useful) defines that proof without requiring the broad artifact matrix on every edit.
