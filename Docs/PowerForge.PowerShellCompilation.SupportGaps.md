The first bounded `switch` slice now recovers only a direct, top-level exact switch over the same authored `[string]` parameter in a Hybrid native function. It rejects preceding commands, member calls, script blocks, and direct rebinding that could remove the parameter's type constraint. A synthetic original/generated probe also removes and recreates the parameter as an array: that function remains hosted. On the unchanged PSSharedGoods packet, `Convert-Size` and the deprecated `Set-EmailBodyReplacement` gain complete methods on both targets, with no previously emitted method or promoted region lost. Only `Convert-Size` has offline original/generated execution proof. `Convert-ExchangeSize` remains hosted because a preceding `Select-String` call prevents the type guarantee. The PowerInfoblox command-result condition still needs success-stream cardinality and local-call qualification; it cannot inherit this parameter-only rule.

A second bounded Hybrid slice collects success records from direct `[Array] $target = foreach (...) { ... }` assignments through the existing native output collector. Unchanged PSSharedGoods `ConvertFrom-ScriptBlock` gained a complete method on both targets and matched four offline original/generated cases on PowerShell 7 and 5.1. A later bounded slice admits direct literal member assignment from conditional statement output, such as `$Data.Properties = if (...) { ... }`. The unchanged PSSharedGoods `Get-ObjectPropertiesAdvanced` gained a complete method and matched offline original/generated cases on both hosts, with its hosted command regions still explicit. Its method replaces a former partial region. The current affected-packet count is **209/282** (`net10.0`) and **208/282** (`net472`); same-input CleanupMonster remains **43/68** on each, with no lost retained-function regions. These figures update only those packets, not the frozen five-module baseline table above. Other typed captures, return transfers, and command-result success streams still need their own contracts. The [assessment](PowerForge.PowerShellCompilation.Assessment.md#milestone-29a-sixth-slice--direct-member-conditional-output-capture) records exact evidence and limits.

The PowerInfoblox local-command switch is a separate success-stream case. A read-only two-function packet with unchanged `Resolve-InfobloxDNSRecordType` and `Get-InfobloxDNSRecordValueField` sources emitted the helper but retained the caller (**1/2** complete methods). The helper can produce one normalized string or terminate; the caller can produce zero records for a valid type with no matching clause, as `lbdn` demonstrates. The current native local-call result is not a proven scalar string value for the switch. Casting it to `string` on the strength of the helper's authored parameter type would hide the zero/many-record and error behavior. Keep the caller hosted until a reusable success-stream transfer and switch-iteration contract is qualified. This packet is a bounded repro, not a fresh full PowerInfoblox census or a generated-artifact comparison.

### Recorded PSSharedGoods triage before hosted literal values

A same-input Hybrid `net10.0` explanation at branch head `158fe3438` reported **209 complete methods and 73 retained functions** among 282 authored functions (JSON SHA-256 `2aa53f6f2769f4e5622ea43a5e948150018e301237980902b9271be480389044`). Of the retained functions, 52 had one reported cause. This predates the hosted literal-value slice; current PSSharedGoods emission is 211/282 below, and these blocker counts have not been recomputed. A sole diagnostic is not a promise that changing that rule alone produces equivalent generated execution: authored state, command effects, and packaging still need artifact proof. The following were distinct retained functions in that packet, unlike the frozen five-packet diagnostic totals above.

| Current sole reported blocker | Retained functions | Next proof or reason to keep hosted |
| --- | ---: | --- |

`Convert-BinaryToIP` is the strongest next in-memory lead in this packet, but its authored `return $null` occurs inside a `try`/`catch` within `@(...)`, and the warning/error paths must be compared before admitting it. Three small standalone sources make the distinction concrete on current `net10.0`: `Get-Date -Format yyyy` has **one typed Strict executable unit** and prior original/generated Windows x64 execution proof; `param([string] $Pattern); Get-Date -Format $Pattern` and `param([int[]] $Values); $Values | ForEach-Object { $_ * 2 }` each have **zero typed Hybrid executable units with hosted root source**, while Strict rejects each. The latter two were explain-only, not built or executed. Their Strict diagnostics respectively identify the nonliteral format boundary and the unqualified pipeline's missing runtime-free assignment contract. A hosted Hybrid script can still run through PowerShell; that is not compiled execution credit. Exact explanation hashes are in the [assessment](PowerForge.PowerShellCompilation.Assessment.md#milestone-29a-current-portfolio-explanations).

**Ordinary command shapes also need attention.** The [module quickstart](PowerForge.PowerShellCompilation.ModuleConsumers.md) uses `Get-Date -Format yyyy`. A fresh one-function Hybrid build on both Windows hosts emits its complete CLR method with one hosted command region; the original and generated imports return the current integer year, and both honor a session function shadowing `Get-Date`. The earlier description of the whole function as retained was too broad. The new bounded intrinsic binds a literal `-Format` to a runtime-free string result only when command identity is safe: a canonical module-qualified call, or an unqualified call in a host-free Strict target without a local shadow. Dynamic formats, PowerShell's named `FileDate*` formats, other parameters, and an unqualified Hybrid call keep runtime resolution. The no-argument `Get-Date` rule remains. PSScriptTools also reports unqualified `Write-Debug`, `Write-Host`, `Write-Warning`, `New-Object`, and `ForEach-Object`; PSSharedGoods reports `Write-Host` and `Select-Object`; `Out-String` is hosted in PSScriptTools. These are observed invocation forms, not claims that every use of each named cmdlet is unsupported.

| Representative source shape | Result or effect to preserve | Current qualified route and remaining gap |
| --- | --- | --- |
| `Get-Date` with no arguments | One local `DateTime` value | Direct runtime-state binding with safe command identity; an unqualified Hybrid call remains session-resolved. |
| `Get-Date -Format yyyy` or a literal .NET pattern | One culture-formatted String | Direct binding with safe identity in this M29a slice; unqualified Hybrid invocation stays a hosted command inside an emitted method when the surrounding function is admissible. Named `FileDate*`, variable formats, and other parameter sets remain outside the rule. |
| PSScriptTools `[OutputType('Name')]`, multiple types, or `ParameterSetName` | Advisory `Get-Command` output metadata, not a value guarantee | Non-whitespace literal string names and resolvable CLR type lists now propagate in source order, including repeated attributes with one literal `ParameterSetName` each, on advisory-metadata-capable Hybrid binary modules. They do not become return-type guarantees. Dynamic, mixed, unresolved CLR type expressions and whitespace-only names remain hosted; runtime-free Strict targets reject advisory-only collections. The 66/60 diagnostic baseline above predates these bounded implementations. |
| Unqualified `Write-Verbose` and related stream commands | Stream records, preferences, command lookup, error behavior | The host owns runtime resolution and stream routing. A reusable hosted command region may permit surrounding CLR code, but its presence is not direct translation of the command. |
| `ForEach-Object` or `Select-Object` with a script block or provider-bound input | Pipeline order/cardinality, `$_`, script-block scope, downstream streams | Bounded native forms need separate proof. Arbitrary unqualified pipeline commands and their session effects remain hosted. |
| Statement output captured into an assignment or return | PowerShell success-stream enumeration and no-output distinction | Direct `[Array] = foreach` and direct literal member `= if` are qualified in Hybrid on both Windows hosts. The 14 syntax diagnostics and three enclosing returns are the frozen baseline, not a fresh residual count; other targets and returns remain outside the proven contract. |

The separate inspect-only external assessment reports **Locksmith 13/44** and **Locksmith2 21/100** complete emitted functions on `net10.0`, with no complete workload execution. Locksmith's unresolved authored AD parameter types must not be admitted by pretending they are CLR types in the generated artifact. Locksmith2 prominently hits unresolved `[OutputType]`, member calls in `catch`, and unavailable `ErrorRecord` reference shapes. `Test-IsADAdmin` and `Test-IssueExists` have documented hosted dispositions in the [assessment](PowerForge.PowerShellCompilation.Assessment.md); they are not safe targets for an AD execution probe. Provider calls such as `Get-AD*`, network requests, prompts, and installer operations remain explicit host/effect boundaries until separately qualified. The external assessment evidence SHA-256 is `5e409b06e136b463caa5dd1c44b47ca852cd2deee579653529e61d0a091ab682`.

For the next implementation selection, split each retained function's co-blockers and identify a safe unchanged-source workflow. The formatted-date quickstart, bounded `[OutputType]` forms, direct string-parameter `switch`, direct `[Array] = foreach` capture, and direct member conditional capture have qualified slices above; their unqualified variants remain explicit. The largest frozen diagnostic group was parameter metadata, but its 66 affected units were **not** 66 ready-to-compile functions. A support claim should name the exact form, mode, host, command-resolution assumption, and remaining PowerShell boundary, then show original/generated behavior and same-input no-loss results. The [M29a checklist](PowerForge.PowerShellCompilation.NextMilestones.md#milestone-29a--make-ordinary-powershell-forms-useful) defines that proof without requiring the broad artifact matrix on every edit.
